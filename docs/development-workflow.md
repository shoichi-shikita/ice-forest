# 開発ワークフロー

本リポジトリでは、タスクを自動化するための開発フローが設定されています。
なお、現時点で**ゲーム本体の実装は行われておらず、ゲームデザインについても確定していません。**
文書1件を対象とした通しテストでは、ActionsからJulesへの依頼、JulesによるPR #3の作成、Codexの自動レビュー完了まで確認できました。ゲームコードの実装・動作検証、通常依頼の計画承認経路、レビュー後の自動再修正は未検証です。

## 開発自動化フロー

基本的な開発の自動化プロセスは以下の順序で進行します：

1. **GitHub Issue / workflow_dispatch**: Issueを作成しただけでは開始しません。開いているIssueに `ai-ready` ラベルを付け、Actionsの「Ice Forest task」をIssue番号付きで手動実行できます。最新の `main` では、リポジトリ所有者が `ai-ready` ラベルを付けたイベントからの自動開始も設定済みです。このラベル起動経路は個別の実動作検証前です。
2. **Jules**: タスクの内容を受け取り、Julesが実装に向けた計画を提案します。
3. **計画の承認**: 通常の実行においては、Julesが提案した計画に対して**必ず人間による承認（human plan approval）が必要**です。
4. **PR作成**: 計画が承認されると、Julesがコードを変更しPull Request（PR）を作成します。
5. **Codex自動レビュー**: 作成されたPRに対して、Codexによる自動コードレビューが実行されます。
6. **手動マージ (Manual merge)**: 自動でマージされることはありません。最終的なPRの確認とマージは人間が手動で行います。

## 初期設定 (Initial Configuration)

このフローを稼働させるための初期設定は以下の通りです：
- リポジトリに対してJulesへのアクセスを許可します。
- GitHub Actionsのシークレットとして `JULES_API_KEY` を設定します。
- 自動化を有効にするため、Actionsの変数 `AUTOMATION_ENABLED` を `true` に設定します。
- リポジトリとCodexを接続し、自動レビューを有効化します。

## 安全メカニズムと制限事項

### エラー時の停止 (Stopping on errors)
APIエラーやタイムアウトなどの予期せぬエラーが発生した場合、自動での再試行は行わず、即座に処理を停止します。

### 重複防止 (Duplicate prevention)
同一のIssueからJulesが複数回起動されることを防ぐため、実行開始時にロック用のコメントを記録し、二重実行を抑止します。

### 利用枠の制限 (Included-plan limits)
連携コードは課金APIや追加購入を呼び出しません。各サービスの既存利用枠を使い、APIエラー時に停止します。Codexの「レビューにクレジットを使用」はOFFにして運用します。アカウント全体の別途設定済み課金まで、このコードが制御するわけではありません。
