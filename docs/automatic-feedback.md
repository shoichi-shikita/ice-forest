# 上限付きの自動修正

PR #4を本人承認によりmainへ統合済みです。Codexのコメントイベントと約30分ごとの確認が有効です。PR #3だけに ai-auto-fix を付けて検証しています。

統合後は、Julesが作成した同一リポジトリ内のPRに `ai-auto-fix` ラベルを付けると、Codexの完了済みレビューを読み、指摘を対応するJulesセッションへ自動送信します。PRとJulesの出力、対象ソースが一致した場合だけ処理します。新しいJulesセッションは作りません。通常の最初の計画承認と最後のマージは人が行います。

Codexのコメントイベントと約30分ごとのGitHub Actionsで確認します。スケジュールには遅延や停止があり、厳密な30分間隔は保証しません。対象がなければ変更もコメントも行いません。PC起動は不要です。

## 上限と停止条件

- PRごとに修正依頼は最大2回、再レビュー依頼も最大2回です。
- 現在のコミットに対する完了済みCodexレビューだけを採用します。
- Julesの修正後は既存の `test` チェック成功を確認して `@codex review` を投稿します。GitHub botからのこの再レビュー依頼がアカウントで受理されるかは実動作検証前です。
- APIのエラーやタイムアウトは自動再送しません。送信前にPRコメントへ記録するため、失敗しても同じコミットでは再送しません。
- 問題なし、上限到達、判定不能、ページ上限到達の場合は、そのPRに追加の依頼を送りません。
- `ai-auto-fix` を外すとそのPRの新規修正依頼を停止します。`AUTOMATION_ENABLED=false` は全体の新規処理を停止します。開始済みJules作業はJules側で停止します。
- 1回の確認は最近更新されたopen PR最大10件、Julesセッション最大500件を対象とします。関連セッションが見つからない場合は送信しません。

## 費用・権限

公開リポジトリの標準ランナーだけを使い、artifact/cacheは作りません。OpenAI API・Gemini Developer API・追加購入は呼びません。Codexの「レビューにクレジットを使用」はOFFを維持してください。アカウント全体の別途設定済み購入までは制御できません。

デフォルトブランチの連携コードだけにキーを渡し、PRのコードは実行しません。修正依頼の対象は元の承認済みタスク内に限定し、権限・課金・ワークフロー・依存関係の変更、マージ、デプロイは依頼しません。モデルへの指示は権限隔離の代わりにならないため、最終PRの人による確認は必要です。
